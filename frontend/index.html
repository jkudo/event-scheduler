配置アルゴリズム説明

自動配置ボタンを押した際に実行されるスタッフ配置アルゴリズムの仕組みを説明します。

全体フロー

1. 既存配置クリア → 2. 希望セッションの先行確保 → 3. セッション順にループ → 4. スタッフをスコアリング → 5. 上位から配置 → 6. 初心者制約の調整

希望セッションの先行確保: 本配置は開始時刻順に処理するため、先に処理されたセッションが希望者を取ってしまいます。これを防ぐため、優先度の高い希望から順に、1人あたり1件だけ先に押さえます。第1希望が満席・時間重複などで確保できない場合は第2希望以降を順に試します。同じ優先度で競合した場合は、希望件数が少ないスタッフを優先します。

部分再配置: 選択したセッションのみを指定して再配置することも可能です。その場合、指定外のセッションの配置は維持されます。

配置前の必須チェック

  • 活動可能時間: スタッフの活動可能時間帯にセッション全体が収まること（未設定の場合は制約なし）
  • 時間重複: 既に配置済みの別セッションと時間が重複しないこと
  • 移動時間: 別部屋のセッションへは最低10分の間隔があること
  • 最大稼働時間: スタッフの合計稼働時間が上限を超えないこと
  • 配置人数: 各セッションに設定された必要人数どおりに配置（必要人数0は配置しない）

スコアリング（優先度の計算）

各スタッフに対してスコアを計算し、スコアが高い順に配置します。

項目スコア説明
希望セッション最大 +100優先度1 = +100, 優先度2 = +80, 優先度3 = +60 ...（先行確保で埋まらなかった分に効きます）

ロールマッチ+5スタッフのロールにセッションの対象ロールが含まれる場合

担当時間均等化-12 / 時間既に担当している合計時間に応じて減点

スコアが同点の場合は、担当件数・合計担当時間が少ないスタッフを優先します。

初心者制約（2段階）

第1段階: 配置時の優先確保

  • 未経験の初心者（経験回数=0）が候補にいる場合、まず経験者を1名優先的に配置
  • その後、残り枠を通常のスコア順で埋める

第2段階: 配置後のスワップ調整

  • 全セッションの配置完了後、初心者のみで構成されたセッションがないかチェック
  • 該当がある場合、同時間帯の別セッションに配置された経験者とスワップ（入れ替え）
  • スワップ先のセッションに経験者が残ることを保証（経験者が1人しかいない場合はスワップしない）

※ 一度経験者と組んでセッションを担当した初心者は「訓練済み」として、以降は経験者扱いになります。

使い方ガイド

推奨: キャッシュ + ポーリング更新

外部サイトではフルデータをキャッシュし、軽量な更新確認エンドポイントをポーリングして変更時のみ再取得する方法を推奨します:

const API_KEY = 'YOUR_API_KEY';
const BASE = 'https://your-domain';
let cachedData = null;
let cachedSnapshotId = null;

// 更新確認（軽量・ポーリング用）
async function checkUpdate() {
  const res = await fetch(BASE + '/public/api/schedule/check?key=' + API_KEY);
  const info = await res.json();
  if (info.snapshot_id && info.snapshot_id !== cachedSnapshotId) {
    await loadSchedule(); // 変更あり → フルデータ再取得
  }
}

// フルデータ取得（初回 or 更新時のみ）
async function loadSchedule() {
  const res = await fetch(BASE + '/public/api/schedule?key=' + API_KEY);
  cachedData = await res.json();
  cachedSnapshotId = cachedData.snapshot_id;
  renderTimeline(cachedData); // 画面を更新
}

// 初回読み込み + 60秒ごとにポーリング
loadSchedule();
setInterval(checkUpdate, 60000);

エンドポイント一覧

エンドポイント用途レスポンス
/public/api/schedule/check?key=...更新確認（ポーリング用）{ snapshot_id, published_at }
/public/api/schedule?key=...フルデータ取得セッション・部屋・グループ・カテゴリ全データ
/public/api/photo/{file}?key=...登壇者写真画像ファイル

GitHub Actions連携

パブリッシュ時にGitHub Actionsの workflow_dispatch を自動で実行し、GitHub Pages等のキャッシュを更新できます。スケジュールAPIのURLはパブリッシュ時に自動で渡されるため、リポジトリのSecretsへの登録は不要です。

設定手順:

  1. 対象リポジトリに workflow_dispatch トリガーのワークフローを作成（下記の例を参照）
  2. GitHub Settings → Developer settings → Fine-grained personal access tokens でトークンを発行
    必要な権限: 対象リポジトリに対して Actions: Read and write
  3. Dispatch URLを取得して入力:
    https://api.github.com/repos/{owner}/{repo}/actions/workflows/{workflow_file}/dispatches
    例: https://api.github.com/repos/myorg/myrepo/actions/workflows/update-schedule.yml/dispatches
  4. Personal Access Tokenを入力して「設定を保存」
Dispatch URLの確認方法: GitHub リポジトリ → Actions → 対象ワークフロー名をクリック。ブラウザのURLが https://github.com/{owner}/{repo}/actions/workflows/{workflow_file} の形式になるので、これを上記の形式に置き換えてください。

ワークフロー例 (.github/workflows/update-schedule.yml):

name: Update Schedule Cache
on:
  workflow_dispatch:
    inputs:
      schedule_url:
        description: "Public API URL (with key)"
        required: true
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Fetch schedule
        run: |
          mkdir -p docs
          curl -sf "${{ inputs.schedule_url }}" \
            -o docs/schedule.json
          echo "Fetched schedule:"
          jq '.snapshot_id, .published_at, (.sessions | length)' \
            docs/schedule.json
      - name: Commit and push if changed
        run: |
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add docs/schedule.json
          if git diff --cached --quiet; then
            echo "No changes to commit"
          else
            git commit -m "Update schedule cache"
            git push
          fi

パブリッシュ時にスケジュールAPIのURL（APIキー含む）が inputs.schedule_url として自動で渡されます。GitHub Actions実行が失敗してもパブリッシュ自体は成功します。

画像のキャッシュについて: 登壇者写真はリクエストのたびにこのサーバーから転送されます。外部サイトで表示する場合は、CDN・リバースプロキシ・サーバーサイドキャッシュ等を利用し、画像を外部サイト側でキャッシュしてください。スケジュールデータ更新時に画像URLも変わらないため、snapshot_id の変更を検知したタイミングでキャッシュを更新する運用を推奨します。

利用方法

Event Schedulerとは

イベントやカンファレンスの運営に必要な、部屋・セッション・スタッフの管理と配置を一元的に行えるツールです。データはすべてサーバー上に保存され、複数人で同時にアクセスできます。

推奨ワークフロー

1
部屋管理で会場の部屋を登録（名前・定員・階数）
2
会場地図で会場のフロアマップ画像を登録
3
設定でカテゴリ・セッショングループを必要に応じて追加（受付案内・懇親会など）
4
全体スケジュール管理で全スタッフ共通のスケジュールを登録（集合・開場・昼休み・閉会など）
5
セッション管理でセッションを登録（タイトル・登壇者情報・時間・部屋・カテゴリ）
6
カテゴリ別管理（受付案内管理・懇親会管理など）で各カテゴリのセッションを登録
7
スタッフ管理でスタッフを登録（担当ロール・英語対応・稼働時間・経験回数・活動可能時間・希望セッション）
8
各担当タブ（セッション担当・受付案内担当・懇親会担当など）で自動配置を実行し、必要に応じて手動調整
9
全体スケジュール・スタッフ別詳細で全体の確認。エクスポートでExcel出力・バックアップ
10
公開APIでスケジュールをパブリッシュし、外部サイトへJSON配信。Webhook・GitHub Actions連携で自動更新も可能

閲覧・確認

全体スケジュール

全カテゴリ・全部屋のタイムテーブルを一画面に表示します。日付タブで日ごとに切り替え、スタッフ絞り込みで特定スタッフの担当を確認できます。

  • セッションをクリックすると詳細ポップアップが開きます
  • 全体スケジュール（overall）のセッションは「全員」または個別スタッフ配置が表示されます
  • 凡例でカテゴリごとの色分けを確認できます

リアルタイム

現在時刻を基準に、いま動いている予定だけを表示します。当日の運営中に開いておく画面です。

  • 進行中: いま実施中の予定。残り時間と進捗バー、その下に担当スタッフを表示
  • まもなく開始: 30分以内に始まる予定。開始までの時間を表示
  • 終了直後: 30分以内に終わった予定
  • 各行に同じ会場の前後1件（前・次）を担当者名つきで表示。その部屋の入れ替わりと引き継ぎ相手が把握できます
  • 行をクリックすると詳細ポップアップが開き、そこでも同じ会場の前後のセッションを確認できます。前後のタイトルをクリックするとその詳細に切り替わります
  • 時刻は1秒ごと、配置は1分ごとに自動更新されます
  • スタッフで絞り込むと、その人の担当と全員対象の予定だけが残ります。選んだスタッフは端末に記憶され、次回開いたときも維持されます
  • 時刻指定: スライダーで任意の時刻に切り替えられます。事前のリハーサルや、当日に「この時間はどうなるか」を確認するのに使えます。指定中は時計がオレンジになり「指定時刻」と表示されます。チェックを外すと現在時刻に戻ります

スタッフ別詳細

スタッフごとの担当セッション一覧を表示します。プロフィール写真・アカウント名・担当ロール・経験回数・活動可能時間とともに確認できます。

  • 「全員」に設定された全体スケジュールは自動的に全スタッフの担当に含まれます
  • 同一時間帯のセッションは 全体 → セッション → カテゴリ順 で表示されます
  • スタッフ絞り込みで特定のスタッフのみ表示できます

会場

登録済みの会場地図を一覧表示します。画像をクリックすると拡大表示されます。

イベント設定

全体スケジュール管理

全スタッフ共通の予定を登録します。スタッフ集合・開場・昼休み・閉会挨拶などのイベント全体に関わるスケジュールです。

  • タイトル・開始/終了時刻・備考を設定
  • 登壇者情報は不要です
  • 既定で全員が対象です。個々のスタッフを配置せず、全スタッフの担当一覧に表示されます。対象を絞る場合は「全員を対象にする」のチェックを外してから個別に配置してください
  • 全体スケジュールマトリクスの「全体」列に表示されます

セッション管理（セッショングループ別）

セッショングループごとにセッションを登録・編集します。セッショングループは設定ページで追加でき、Day 1 / Day 2 のような論理的なグループ分けに使用します。

  • 基本情報: タイトル・登壇者名・ふりがな・開始/終了時刻・部屋・カテゴリ
  • 登壇者詳細: 所属・肩書き・プロフィール・写真アップロード
  • カテゴリ: 一般・ワークショップ・基調講演・基調講演（複数人）・LT・パネルディスカッション から選択
  • 複数登壇者の形式: カテゴリを「LT」「パネルディスカッション」「基調講演（複数人）」にすると登壇者を個別に追加可能。各登壇者に開始/終了時刻・写真を設定
  • 必要スタッフ数: 手動入力。スタッフ管理の「必要スタッフ計算」で担当ごとに必要人数・現在の担当人数・不足を確認できます
  • 英語対応: チェックすると英語対応可能なスタッフが優先配置されます
  • 日付タブはセッションの日付から自動生成されます

カテゴリ別管理（受付案内・懇親会など）

設定で追加した動的カテゴリのセッション管理です。受付案内・懇親会・デモなど、セッションとは別のテンプレートで管理されます。

  • タイトル・開始/終了時刻・部屋・必要スタッフ数・英語対応・備考を設定
  • 登壇者情報やLT機能はありません
  • 日付タブはそのカテゴリのセッション日付から自動生成されます

スタッフ管理

運営スタッフの登録・編集を行います。

  • 基本情報: 名前・アカウント名（@自動付与）・プロフィール写真
  • 担当ロール: セッション・受付案内・懇親会などの担当可能なロールを選択（複数選択可）。自動配置時にロールに基づいて適切なセッションに配置されます
  • 英語対応: 英語セッションに優先配置されます
  • 最大稼働時間: 1日の最大稼働時間を設定。自動配置時にこの時間を超えないよう調整されます
  • 過去参加回数: 0回が初参加。初参加スタッフは経験者と一緒に配置されます
  • 活動可能時間: スタッフの対応可能な時間帯を設定。この時間帯のセッションのみ配置対象になります
  • 希望セッション: 担当したいセッションを優先度付きで登録。自動配置時に考慮されます

部屋管理

会場の部屋を登録・編集・削除します。

  • 名前: 部屋名（メインホール、Room Aなど）
  • 定員: 収容人数
  • 階数: 自動配置で階移動ペナルティに使用。連続セッションで階が異なるスタッフは減点されます

会場地図

会場のフロアマップ画像を登録します。名前（必須）と画像ファイルをアップロードします。「会場」タブや受付案内の印刷物で表示されます。

スタッフ配置

全体スケジュール担当

全体スケジュールのセッションへのスタッフ配置を管理します。

  • 全員: 担当スタッフの「＋追加」から「全員」を選択すると、全スタッフが対象のセッションとして表示されます。個別にスタッフを登録する必要はありません
  • 「全員」設定は解除ボタン（x）で個別配置に戻せます
  • ロック/編集切替でスタッフの追加・削除を制御できます
  • 日程タブで日付を選ぶと配置表（マトリクス）、全日程では一覧を日別に分けて表示します

セッション担当（セッショングループ別）

セッショングループごとのスタッフ配置を管理します。

  • 自動配置: 「自動配置」で一括配置。「選択再配置」で選んだセッションだけ、「未配置」で埋まっていないセッションだけを配置。「クリア」で配置を全て解除
  • 手動配置: ロックを解除し、各セッションの「＋追加」からスタッフを個別に追加
  • 配置クリア: 現在の配置をすべて解除
  • ドラッグ&ドロップでセッションの時間・部屋を変更可能
  • スタッフ絞り込みで特定スタッフの配置状況を確認できます

カテゴリ別担当（受付案内・懇親会など）

動的カテゴリのセッションへのスタッフ配置です。セッション担当と同じ操作で自動配置・手動配置が可能です。スタッフの「担当ロール」に該当カテゴリが含まれているスタッフのみが配置対象になります。

配置アルゴリズム

自動配置アルゴリズムの仕組みを説明するページです。以下の要素を総合的にスコアリングして最適配置を算出します。

  • ロールマッチ: スタッフの担当ロールとセッションカテゴリの一致
  • 希望セッション: 高優先度の希望ほど高スコア
  • 英語対応: 英語セッションには英語対応スタッフを優先
  • 担当均等化: 担当件数・合計担当時間が少ないスタッフを優先
  • 階移動ペナルティ: 連続セッションの階差が大きいほど減点
  • 活動可能時間: 設定された時間帯のみ配置対象
  • 最大稼働時間: 超過しないよう制御
  • 初参加者保護: 初参加スタッフは経験者と一緒に配置

公開API

概要

イベント公式サイト等の外部サイトからスケジュールデータをJSON形式で取得できるAPIを提供します。「パブリッシュ」で確定したスナップショットのみが公開されるため、編集中のデータは外部に漏れません。

API設定

  • 有効/無効: 公開APIの有効・無効を切り替え。初回有効化時にAPIキーが自動生成されます
  • APIキー: クエリパラメータ ?key= またはヘッダー X-API-Key で認証に使用。コピー・再生成が可能
  • CORSオリジン: *（全許可）またはカンマ区切りで許可するオリジンを指定

パブリッシュ

  • 「パブリッシュ」ボタンで現在のスケジュールデータをスナップショットとして保存・公開
  • パブリッシュ履歴から過去のスナップショットをアクティブに切り替え可能
  • アクティブでないスナップショットは削除可能

Webhook

パブリッシュ時に指定URLへPOSTリクエストを送信します。外部サイトのキャッシュ更新トリガー等に利用できます。送信失敗時もパブリッシュは成功します。

GitHub Actions連携

  • パブリッシュ時に workflow_dispatch を実行し、GitHub Pages等のキャッシュを自動更新
  • スケジュールAPIのURLは inputs.schedule_url としてワークフローに自動で渡されます
  • Dispatch URL: https://api.github.com/repos/{owner}/{repo}/actions/workflows/{file}/dispatches
  • Personal Access Token: Fine-grained PAT。必要な権限は Actions: Read and write
  • 実行失敗時もパブリッシュは成功します

出力

エクスポート/インポート

  • Excelエクスポート: 部屋管理・セッション管理・スタッフ管理・セッション配置・全体スケジュールマトリクス・カテゴリ別シートを含むExcelファイルを出力。登壇者写真も埋め込まれます
  • スタッフインポート: スタッフ管理シートと同じ列構成のExcel/CSVを一括登録。同名はスキップ。写真・希望セッションは対象外
  • セッションインポート: セッション管理シートと同じ列構成のExcel/CSVを一括登録。同タイトル・同開始時刻はスキップ。未登録の部屋・グループは自動作成。カテゴリ・担当は登録済みの名前のみ指定できます
  • エクスポートしたExcelファイルはそのままインポートに使用できます

バックアップ

  • 手動バックアップ: 全データと画像ファイルをZIP形式でエクスポート。別環境への移行やデータ保全に使用します
  • バックアップ復元: エクスポートしたZIPファイルからデータを復元。既存データはすべて上書きされます
  • 自動バックアップ: 一定間隔（分単位）または毎日指定時刻に自動でバックアップを実行。保持件数を超えると古いバックアップから自動削除されます
  • バックアップ履歴: 過去のバックアップ一覧を表示。個別にダウンロード・削除が可能です

システム

設定

  • イベントタイトル: サイドバー上部に表示されるタイトルを変更
  • アイコン: サイドバー上部とブラウザタブに表示する画像を登録。ファイル選択またはCtrl+Vで貼り付け（jpg・png・gif・webp）
  • カテゴリ管理: 受付案内・懇親会・デモなどのカスタムカテゴリを追加・編集・削除。表示名・色・順序を設定。セッションが紐づいているカテゴリは削除できません
  • セッショングループ管理: セッションの論理グループを追加・編集・削除。日付・表示名・色・順序を設定。サイドバーにグループごとの管理・担当タブが自動追加されます
  • 順序: 追加時は自動で末尾に設定。既存の順序を指定すると、その位置に挿入され他の項目は自動的にずれます
  • パスワード変更: 管理者パスワードを変更
  • 全データ初期化: パスワードを入力してすべてのデータを削除。事前にバックアップを取ってください

セッション詳細ポップアップ

セッション名をクリックすると表示される詳細ポップアップでは、以下の情報を確認・操作できます。

  • セッション基本情報（タイトル・時間・部屋・カテゴリ・必要人数）
  • 登壇者情報（写真・名前・所属・肩書き・プロフィール）※全体セッションを除く
  • 登壇者一覧（LT・パネルディスカッション・基調講演（複数人）の場合）
  • セッション説明・備考
  • 担当スタッフの確認・追加・削除（ロック解除時）
  • 全体セッションの場合は「全員」の設定・解除が可能

Tips

  • 各担当タブのロック/編集切替で誤操作を防止できます。ロック中は配置の変更ができません
  • アカウント名は入力時に@が自動付与されます（例: tanaka → @tanaka）
  • 登壇者・スタッフの写真は選択時にプレビュー表示され、保存時にアップロードされます
  • 開始時刻を設定すると終了時刻が自動計算されます（セッション: +1時間、LT: +5分）
  • バックアップは定期的にエクスポートすることを推奨します。ZIPにはすべてのデータと画像が含まれます
  • データの初期化は元に戻せません。必ずバックアップを取ってから実行してください
